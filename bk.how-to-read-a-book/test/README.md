# semtree organization candidates

Research run (2026-08-28): what is the best semtree/taxonomic structure for a
WikiBonsai knowledge layer? Three candidate reorganizations of this bed's
bonsai, each built from ONE organizing principle, using the same node set as
the live tree (`bonsai/index/`). These are specimens, not planted — only one
tree can be live at a time (semtree requires each node appear once), so pick
one and let the web (`: attrs ::`) carry the other principles.

## research anchors

- **Aristotle → Porphyry (categorical).** The first systematic organization of
  knowledge: genus–differentia definition, and the Porphyrian tree (substance →
  corporeal → animate → ... → human) as the original "is-a" hierarchy. Rule of
  a clean taxonomy: every child IS-A parent, siblings split by one differentia
  at a time. Aristotle also supplies the escape hatch when pure categories
  strain: the **four causes** (material = what it's made of, formal = what
  shape it takes, efficient = what produced it, final = what it's for) — i.e.
  he knew categories alone don't capture processes, which is exactly where
  candidate A creaks and candidates B and C come from.
- **Linnaeus → Darwin (causal-genetic).** Linnaeus applied Aristotelian
  logical division to life — similarity-based ranks. Darwin's single figure in
  the *Origin* re-grounded that tree: the hierarchy is real because it records
  **descent with modification**. The deep lesson (and cladistics made it a
  method): a "natural" classification is one whose is-a structure is
  *generated by an underlying causal process*; similarity clusters BECAUSE of
  common descent. Categorical in form, causal in justification.
- **Musk's semantic tree / first principles (epistemic dependency).** "View
  knowledge as a semantic tree — make sure you understand the fundamental
  principles, i.e. the trunk and big branches, before you get into the
  leaves/details or there is nothing for them to hang on to." Same structure
  as Darwin's, but the causality is epistemic: children *depend on* parents
  for intelligibility. This is the trunk→leaves reading of a prerequisite
  hierarchy (Gagné's learning hierarchies / Knowledge Space Theory are the
  formal versions — see the `pedagogical-ordering` design notes: intra-branch
  order = tree traversal, cross-branch dependency = `: prereq ::` DAG).
- **Ranganathan (facets).** Any single tree eventually hits polyhierarchy
  pressure (a node that belongs under two parents for two different reasons).
  Faceted classification says: those are different *axes*, not competing
  parents. In WikiBonsai the tree picks one axis; the other facets live in the
  web as typed attrs. This is the TERMS.md tree ⊥ web separation doing real
  philosophical work.

## the synthesis

"At first glance the tree is just categorical, but the connection to causality
is important" — the history agrees. The great knowledge trees are **categorical
in form but causal in justification**: Darwin's taxa are similarity classes
*explained by* descent; Musk's branches are topic clusters *ordered by*
dependency; Adler's four levels are kinds of reading that are explicitly
**cumulative** (each level contains and presupposes the one below — his words).
So the question "categories or causality?" is a false choice; the real design
question is *which* causal process should generate the tree's shape, with the
remaining relations pushed into web attrs (`: prereq ::`, `: serves ::`,
`: kind ::`).

## candidates

| | principle | ancestry | edge reads as | strength | weakness |
|---|---|---|---|---|---|
| A `i.candidate-a-categorical.md` | pure taxonomy | Aristotle/Porphyry/Linnaeus | "is a kind of" | retrieval, typing — feeds dynamic-ontology (doctype projection) directly | processes don't taxonomize; steps get shoehorned into "kinds of acts" |
| B `i.candidate-b-causal.md` | cumulative skill-descent | Darwin/Musk/Gagné | "grows out of / is built from" | matches Adler's own claim that levels are cumulative; traversal = curriculum | deep nesting; sequential steps read as long chains; kinds lose their shelf |
| C `i.candidate-c-teleological.md` | final cause: ends → means | Aristotle's telos; Adler's four questions | "serves the end of" | most faithful to Adler's *spirit* (goals-first); great practice checklist | shared means (active reading serves every end) force arbitrary placement |

## recommendation

For this bed: **plant B**, the causal spine. *How to Read a Book* is itself a
skill-building method and Adler insists the levels are cumulative — so the
causal tree is the book's own deep structure, and root→leaf traversal yields
the learning sequence for free (blurry-to-sharp). Keep the other two
principles in the web, where they're one attr away:

- teleology → `: serves :: [[read-for-understanding]]` on each act
- taxonomy → `: kind :: [[reading-act]]` (or doctype, once dynamic-ontology
  projection lands — note a taxonomic tree is what that feature projects best,
  which is the strongest argument for A in ontology-heavy gardens)
- cross-branch dependency → `: prereq ::` (e.g. criticize prereqs interpret
  even if a future reorg moves them apart)

General rule extracted for WikiBonsai knowledge layers: **choose the tree
principle by what you want traversal to mean** — curriculum (causal), catalog
(categorical), or checklist (teleological) — and demote the other two axes to
typed attrs.
